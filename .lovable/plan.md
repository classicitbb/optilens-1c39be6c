# Fix the recurring Internal Server Error (Copilot / admin resource tools)

## What's actually broken

The error is not a preview hosting problem — the frontend build is clean and the dev server serves fine. It is a real defect in the shared admin-resource tool dispatcher that backs Iris/Copilot and the MCP tools.

`supabase/functions/_shared/copilot/adminResources.ts` line 712 reads:

```text
if (resource.financialData && !access.canAccessFinancialData) { ... }
```

but `access` is not a parameter of `dispatchAdminResourceTool`. The function signature is `(db, name, input, actorUserId)` — the fifth `access` argument was dropped while callers still pass it (`portal-copilot/index.ts:191` passes `{ canAccessFinancialData }`).

Result: every tool call except `admin_list_resources` throws `ReferenceError: access is not defined`, and the edge function returns 500. It reproduces on every build because it is a permanent code error, not a transient one.

The deno typecheck confirms this: `adminResources.ts(712,34): error TS2304: Cannot find name 'access'.`

A second, unrelated typecheck failure also blocks clean function verification:
`statement-document-worker/index.ts` — `autoTable` imported from `npm:jspdf-autotable@5.0.8` is typed as a namespace, so the four `autoTable(doc, …)` calls fail `deno check`.

## The fix

1. Restore the missing parameter on `dispatchAdminResourceTool`:
   `(db, name, input, actorUserId?, access: AdminResourceAccess = { canAccessFinancialData: false })`.
   Defaulting to `false` keeps the financial gate closed for callers that don't pass it, so restricted data is never widened by accident.
2. Update the internal callers that legitimately act on behalf of an already-authorised admin (`docStudioTools.ts`) to pass an explicit access object rather than relying on the default, so Doc Studio writes keep working.
3. Update `src/lib/mcp/tools/*` callers (`admin-search-records`, `admin-get-record`, `admin-write-record`) to pass the caller's financial-data capability instead of silently taking the default.
4. Fix the `jspdf-autotable` call sites in `statement-document-worker` with the correct default-import interop typing so `deno check` passes.
5. Redeploy the affected edge functions (`portal-copilot`, `statement-document-worker`) and re-run the deno typecheck to confirm zero errors.

## Verification

- `deno check` on the functions reports no errors (currently 5).
- Existing unit tests in `src/tests/unit/adminResources.unit.test.ts` and `src/tests/integration/irisFinancialDataAccess.integration.test.ts` pass unchanged.
- Live check: run an Iris/Copilot admin query that hits `admin_search_records` and confirm a 200 rather than a 500.
- Confirm a financial-data resource is still refused when the capability is absent.

## Note on the staging MCP copy

`supabase/functions/mcp-staging/index.ts` contains a generated inlined copy of the dispatcher that has no financial-data gate at all. It is regenerated by `npm run mcp:generate`; regenerating it after the fix brings it back in line. Flagging it rather than hand-editing the generated file.
